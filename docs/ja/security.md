# セキュリティモデル

NextMQTT は独立したクリーンルーム実装です。セキュリティ報告と強化に関する質問は、
リポジトリの非公開アドバイザリ経由で受け付けます。

## 信頼境界

| 境界 | 保護 |
| --- | --- |
| MQTT クライアント → ブローカー | 任意の TLS、パスワード/JWT 認証、トピック ACL |
| ブラウザー → ダッシュボード | Bearer トークンまたは API キー、任意の HTTPS |
| ノード → ノード | HMAC-SHA256 署名、共有シークレット、任意の HTTPS |
| 運用者 → コンテナ | 非 root UID 10001、ケーパビリティ削除、任意の読み取り専用ルート |
| ビルド → リリース | CI のコンプライアンススキャン、CodeQL、固定依存、OCI 来歴 |

## 強化チェックリスト

### 資格情報

- [ ] 強力な `NEXTMQTT_ADMIN_PASSWORD` か、事前ハッシュの
      `Admin:PasswordHash` を設定する
- [ ] `NEXTMQTT_ADMIN_TOKEN_SECRET` を全ノード共通のランダム値にする
- [ ] `.env`、証明書、秘密鍵、API キーをコミットしない
- [ ] 漏えいが疑われる場合は管理者パスワードとトークンシークレットを交換する
- [ ] 可能ならハードウェア保護のシークレットストアを使う

シークレットを生成します：

```bash
openssl rand -base64 32
```

### MQTT アクセス

- [ ] 匿名アクセスを無効にする
- [ ] 既定拒否にして明示的な ACL ルールを追加する
- [ ] 信頼できるネットワーク外のクライアントには TLS を必須にする
- [ ] メモリ予算に合ったセッション制限を設定する
- [ ] 接続レート制限を強制するゲートウェイを検討する

### ダッシュボード

- [ ] HTTPS とネットワーク制限の背後に置く
- [ ] トークンの価値が高い場合は `Admin:TokenLifetimeMinutes` を短くする
- [ ] 公開する場合は `Admin:MetricsRequireAuth` で `/metrics` を保護する
- [ ] `/internal/cluster/*` を公開しない
- [ ] CORS を自分のダッシュボードのオリジンに限定する

### クラスタ

- [ ] 環境ごとに一意な 16 文字以上のシークレットを使う
- [ ] 時計を NTP で 5 分以内に同期する
- [ ] プライベートネットワーク外では HTTPS の Advertise URL を使う
- [ ] ingress で内部クラスタパスを遮断する
- [ ] メンテナンス時間にシークレットを交換する

### コンテナと Kubernetes

- [ ] UID 10001 で実行する（イメージの既定）
- [ ] `allowPrivilegeEscalation: false` と全ケーパビリティ削除を維持する
- [ ] CPU/メモリ制限を設定する
- [ ] 読み取り専用ルートと書き込み可能な `/tmp`、`/app/data` を使う
- [ ] NetworkPolicy かより厳しい egress ルールを適用する
- [ ] 資格情報に `existingSecret` / 外部シークレットオペレーターを使う

## 認証の詳細

### パスワードハッシュ

PBKDF2-SHA256、ランダムな 16 バイト salt、既定 210,000 回反復。エンコードされた
ハッシュは反復回数を保持し、検証は定数時間比較を使います。

### JWT

受け付けるのは HS256 のみ。既定で `exp` が必須で、`nbf`、`iss`、`aud` を検証し、
`sub` クレームが主体になります。共有シークレットは
`Authentication:Jwt:Secret` で設定します。

管理者トークンシークレット、クラスタシークレット、JWT シークレットを再利用しないで
ください。

### 管理者トークン

ダッシュボードトークンは `Admin:TokenSecret` で署名された HS256 JWT です。`admin`
ロールを持ち、REST API ミドルウェアだけが受け付けます。API キーは SHA-256
ダイジェストで照合され、管理者トークンと同じ力を持つ Bearer 資格情報として扱います。

## データの扱い

- ペイロードは不透明なバイト列で、既定ではログに残しません。
- MQTT ユーザープロパティとメタデータは保持されます。トピック名やユーザープロパティに
  秘密を入れないでください。
- ダッシュボードはトピック名とペイロードサイズを表示し、内容は表示しません。
- セッション、キュー、retained はメモリにあり、設定次第でファイルストアにも入ります。
  クラッシュダンプやデータボリュームに含まれ得るため、アクセスを制限してください。
- クラスタの重複排除キャッシュは最大 10 分間メッセージ ID を保持します。

## サービス拒否への配慮

ブローカーはパケットサイズ、inflight ウィンドウ、オフラインキュー、送信チャネルを
制限し、CONNECT タイムアウトと keep-alive も強制します。送信元アドレスごとの接続
レート制限、クライアントごとの公開レート制限、トピッククォータは `RateLimits` で
利用できますが既定では無効です。次と組み合わせてください：

- ネットワークポリシーとロードバランサーの制限
- エッジでの接続レート制限
- 大きなペイロードを受け付ける前の認証
- コンテナのリソース制限

## 脆弱性の報告

GitHub の非公開脆弱性報告を使います：

<https://github.com/cn-cam/next-mqtt/security/advisories/new>

バージョン、導入形態、再現手順、影響を含めてください。未修正の脆弱性を公開 issue に
しないでください。
