# ロードマップ

ロードマップは意図であり、契約ではありません。優先度は本番からのフィードバックと
セキュリティ要件に従います。

## 0.1 — 基盤

- [x] MQTT 3.1.1 と 5.0（TCP、TLS、WebSocket、セキュア WebSocket）
- [x] QoS 0/1/2、retained、遺言、セッション期限
- [x] 共有サブスクリプションと MQTT 5 購読オプション
- [x] パスワード、JWT、匿名認証
- [x] アイデンティティプレースホルダー付きの順序付きトピック ACL
- [x] Gossip メンバーシップと署名付きノード間ルーティング
- [x] REST API と Vue 3 ダッシュボード
- [x] CLI、Docker、Compose、Kubernetes、Helm
- [x] Prometheus メトリクス、ヘルスプローブ、構造化ログ

## 0.2 — 永続化と運用

- [x] 追記ジャーナルによるファイル retained ストア（0.4.0）
- [x] 起動時とファイル肥大時のジャーナル圧縮（0.4.0）
- [x] キューと購読を復元する永続セッションスナップショット（0.5.0）
- [x] クラッシュおよび全クラスタ再起動からの復旧のためのファイルセッションレプリカ
- [ ] SQLite と PostgreSQL プロバイダー
- [x] retained とセッション状態のバックアップ/リストア（0.5.0）
- [x] inflight の確認を待つ正常ドレイン（0.5.0）
- [x] クライアント単位と IP 単位の接続レート制限（0.3.0）
- [x] クライアント単位のメッセージレートクォータ（0.3.0）
- [x] トピック単位の公開クォータ（0.5.0）
- [ ] 公開と配信経路の OpenTelemetry トレース

## 0.3 — プロトコルの深化

- [x] 差し替え可能なプロバイダーによる拡張認証（`AUTH`、0.8.0）
- [x] 送信トピックエイリアス
- [x] response-topic の request/response ヘルパー（0.9.0）
- [ ] MQTT over QUIC の実験
- [x] ノード間のグローバル共有サブスクリプション調整
- [x] クラスタ対応の retained tombstone と last-write-wins（0.7.0）
- [x] クライアント単位の購読識別子上限

## 0.4 — 統合

- [x] NATS ブリッジモジュール（0.14.0）
- [x] Kafka ブリッジモジュール（0.15.0、ADR 0007）
- [x] RabbitMQ ブリッジモジュール（0.16.0、ADR 0008）
- [x] ルーティングアクション：トピックフィルタの drop と接頭辞 rewrite
- [ ] ペイロードのエンリッチメントとスキーマ検証
- [x] マニフェストと回収可能なローディングを備えたファーストパーティのプラグイン
  ホスト（0.12.0）

  [機能一覧](features.md#拡張性)を参照してください。

## 明確な非目標

- 他社ブローカーのプライベートプラグイン API との互換性。
- 他社ブローカーの設定ファイルやダッシュボードの再利用。
- 他の実装からのソース、テスト、ドキュメントの複製。
- ブローカーベンダーによる認証や推奨の主張。

## ロードマップへの影響の与え方

次の内容を添えてディスカッションを開いてください：

- ワークロード（クライアント数、メッセージレート、ペイロードサイズ、保持期間）
- 導入先（単体、Kubernetes、エッジ）
- 解消したい運用上の課題
- コンプライアンス上の制約

セキュリティ修正は常に機能開発より優先されます。
