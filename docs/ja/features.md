# 機能一覧

このページは現在のリリースにおける実装の契約です。完全に実装済みのもの、一部のみ、
計画中のものを分けて示すので、導入判断を宣伝文句に頼らずに行えます。

凡例：✅ 実装済み · ⚠️ 一部実装または文書化された制限あり · ❌ 未実装

## 拡張性

NextMQTT はプロセス内の拡張インターフェースとプラグインホストの両方を提供します。
プラグインは `plugin.json` マニフェストから契約バージョン 1 の回収可能なコンテキストへ
読み込まれます。存在しないアセンブリや異なる契約バージョンを指すマニフェストは
スキップされます。

| 拡張ポイント | インターフェース | 用途 |
| --- | --- | --- |
| クライアント認証 | `IClientAuthenticator` | ユーザー名/パスワードと API キー検証の置換・拡張 |
| トピック認可 | `ITopicAuthorizer` | クライアント単位で pub/sub を許可・拒否 |
| クラスタルーティング | `IClusterRouter` | HTTP 転送方式の置換 |
| プラグインのライフサイクル | `IPluginLifecycle` | ロードコンテキストのアンロード前にリソースを解放 |

インターフェースは DI から解決されるため、実装を直接組み込むこともできます。
プラグインは再ビルドを避けるディスク上の手段です：`Plugins:Authenticator` と
`Plugins:Authorizer` が有効化する型を指定し、`POST /api/v1/plugins/reload` が
再起動なしで反映します。プロセス外の連携にはバージョン付き REST API（`/api/v1`）と
クラスタエンドポイント（`/internal/cluster`）を使います。

## 既知の制限

- 送信 `inflight` の確認状態はノード間で移行しません。これらのメッセージはキューから
  再送され、二重に届くことがあります。PUBREL を待つ受信 QoS 2 の公開はセッションと
  一緒に移行します。
- レプリカの新しさは `Cluster:SessionReplicaSeconds` に依存します。
  `Storage:Replicas:Mode=File` がない場合、全ノードの再起動で失われます。
- クラスタ転送はベストエフォートです。共有サブスクリプションはノード間で調整します。
- ノード間の順序保証も exactly-once もありません。
- プロセス内の拡張はソース変更と再ビルドが必要です。プラグインホストが実行時の
  代替手段です。
- 既定の設定は開発向けです。ブローカーを公開する前に必ず強化してください。
