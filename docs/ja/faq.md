# FAQ

## 既存製品のフォークですか？

いいえ。OASIS MQTT 3.1.1/5.0 の独立したクリーンルーム実装です。他社 Broker の
ソース、設定形式、ドキュメント、ロゴ、商標を含みません。

## 本番利用できますか？

プロトコル、認証、ACL、クラスタはテスト済みで、CI でイメージを検証しています。
永続化は任意です。retained、永続セッション、セッションレプリカをディスクへ保存でき、
送信 inflight の確認はクライアントが再送します。記録系として使う前にファイルストアを
有効にし、ボリュームを計画してください。

## 対応クライアントは？

MQTT 3.1.1/5.0 準拠の任意のクライアント：

- `mqtt://host:1883`
- `mqtts://host:8883`
- `ws://host:8083/mqtt`
- `wss://host:8084/mqtt`

## クラスタは exactly-once ですか？

いいえ。MQTT QoS はクライアントと Broker の間です。ノード間転送はベストエフォート
HTTP で、重複排除キャッシュを使用します。

## 共有サブスクリプションはクラスタ全体ですか？

クラスタ全体で調整されます。メッセージごとに共有グループ内の 1 ノードが選ばれるため、
同じグループの別ノードへ重複配信されません。

## 状態はどこに保存されますか？

既定はメモリのみです。`Storage:Retained:Mode=File`、`Storage:Session:Mode=File`、
`Storage:Replicas:Mode=File` を設定すると、対応するデータをボリューム上のジャーナル
またはスナップショットへ保存します。データベースや WAL はありません。ファイルストアを
有効にしない場合、再起動でセッション、キュー、retained が消えます。

## 管理パスワードを忘れた

`NEXTMQTT_ADMIN_PASSWORD` を設定して再起動してください。

## 再起動後に UI トークンが無効

`NEXTMQTT_ADMIN_TOKEN_SECRET` が未設定で一時キーが生成されたためです。固定値を
設定してください。

## 匿名を無効にしたら接続できない

`Authentication:Users` または JWT を設定してください。管理パスワードは MQTT の
認証情報ではありません。

## SUBSCRIBE が 0x87

ACL がフィルタを拒否しています。購読ルールは要求フィルタを包含する必要があります。

## retained が消えた

空 payload で削除、期限切れ、レプリケーション先の停止、上書きのいずれかです。

## セキュリティ報告

公開 issue ではなく GitHub の private vulnerability reporting を使用してください。
