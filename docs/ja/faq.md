# FAQ

## NextMQTT は既存製品のフォークや再実装ですか？

いいえ。OASIS MQTT 3.1.1 と 5.0 仕様の独立したクリーンルーム実装です。他の MQTT
ブローカーのソースコード、ドキュメント文、設定形式、ロゴ、商標は含まず、提携や認証も
主張しません。

## 本番利用できますか？

プロトコル、認証、ACL、クラスタの経路はユニットテストとループバック統合テストで
覆われ、コンテナイメージは CI でビルドされます。永続化は任意です。retained、永続
セッション、セッションレプリカをディスクへ保存でき、アウトバウンド inflight の確認は
クライアントが再送します。記録系として使う前にファイルストアを有効にし、ストレージを
計画してください。

## なぜ .NET ですか？

.NET ランタイムは成熟した非同期ソケット、`System.IO.Pipelines`、高性能な UTF-8 と
暗号プリミティブ、単一ファイル配置モデルを提供します。ブローカーと API は VM も外部
データベースもなしに 1 プロセスで動きます。

## どの MQTT クライアントが使えますか？

準拠した MQTT 3.1.1 または 5.0 のクライアントライブラリなら何でも使えます。接続先：

- `mqtt://host:1883`
- `mqtts://host:8883`（TLS 有効時）
- `ws://host:8083/mqtt`
- `wss://host:8084/mqtt`（HTTPS 設定時）

同梱の `nextmqtt` CLI もクライアントで、スモークテストに便利です。

## 1 ノードで何接続まで扱えますか？

ペイロードサイズ、QoS、購読数、ハードウェアに依存します。設計目標は、適度な CPU で
ノードあたり数万のアイドルまたは低頻度クライアントです。`nextmqtt bench` で自分の
ワークロードを測り、オフラインキューと retained ペイロードのメモリを監視してください。
コード上の固定接続上限はありません。

## クラスタは exactly-once を保証しますか？

いいえ。MQTT QoS はクライアントとブローカーの間に適用されます。ノード間転送は重複
排除キャッシュ付きのベストエフォート HTTP です。ピア障害時、そこへ向かうメッセージは
失われることがあります。ローカルの QoS 1/2 意味論は維持されます。

## 共有サブスクリプションはノードをまたげますか？

はい。ノードは heartbeat で共有グループを広告し、各メッセージはクラスタ全体のグループ
内の 1 メンバーに割り当てられます。ノードごとに 1 回ではありません。
[クラスタ](/ja/clustering)を参照してください。

## 状態はどこに保存されますか？

既定はメモリです。`Storage:Retained:Mode=File`、`Storage:Session:Mode=File`、
`Storage:Replicas:Mode=File` を設定すると、対応するデータをボリューム上のジャーナル
またはスナップショットへ保存します。データベースや WAL はありません。ファイルストアを
有効にしない場合、再起動でセッション、キュー、retained が消えます。設定とシークレットは
環境変数、Compose ファイル、Kubernetes オブジェクトにあります。

## 管理者パスワードをリセットするには？

`NEXTMQTT_ADMIN_PASSWORD` を設定して再起動します。`Admin:PasswordHash` を使う場合は
新しいハッシュを生成します：

```bash
dotnet run --project src/NextMqtt.Cli -- hash-password --password 'new-password'
```

## 再起動後にダッシュボードのトークンが無効になったのはなぜ？

`NEXTMQTT_ADMIN_TOKEN_SECRET` が未設定で、ブローカーが一時的な署名鍵を生成したため
です。全ノードに固定のシークレットを設定してください。

## 匿名を無効にしたらクライアントが接続できないのはなぜ？

少なくとも 1 つの MQTT 資格情報ソースが必要です：

- `Authentication:Users` のローカルユーザー、または
- `Authentication:Jwt:Secret` の JWT シークレット。

ダッシュボードの管理者パスワードは MQTT の資格情報ではありません。

## SUBSCRIBE が `0x87` を返すのはなぜ？

ACL がフィルタを拒否しています。購読ルールは要求フィルタを*包含*する必要があります。
[認証と ACL](/ja/authentication#セマンティクス)を参照してください。

## retained メッセージが消えたのはなぜ？

- 空ペイロードで公開された（retained 状態を削除）。
- メッセージ期限が過ぎた。
- 他のピアが停止しているノードで公開され、複製されなかった。
- 後の公開で置き換えられた。

## 別オリジンからダッシュボードを使えますか？

`Server:Http:AllowedOrigins` にオリジンを追加します。Vite 開発サーバーは既定で
`http://localhost:5173` です。CORS は認証の代わりにはなりません。

## コンテナのポートはどう設定しますか？

環境変数を使います。例：

```bash
NEXTMQTT_SERVER__HTTP__PORT=9090
NEXTMQTT_SERVER__TCP__PORT=11883
```

Docker/Kubernetes でも同じコンテナポートを公開することを忘れないでください。

## テレメトリーやライセンスキーは必要ですか？

テレメトリーなし、ライセンスサーバーなし、実行時の外部依存なしです。プロジェクトは
Apache-2.0 です。

## セキュリティ問題はどう報告しますか？

公開 issue ではなく GitHub の非公開脆弱性報告を使います。
[SECURITY.md](https://github.com/cn-cam/next-mqtt/blob/main/SECURITY.md)を参照して
ください。
